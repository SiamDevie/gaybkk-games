# 🎲 GAYBKK GAMES — กติกาเกม 11 เกมแรก (Game Rules & Design Specification)

> **โครงการ:** `gaybkk-games` · **เว็บไซต์:** `games.gaybkk.co` · **ผู้ดูแล:** gaybkk.co<br />
> **ฉบับ:** Proposed MVP v1.0 · **สถานะ:** Product/Game Design Specification — **ยังไม่ได้ยืนยันว่าพัฒนาเสร็จ**<br />
> **กลุ่มเป้าหมาย:** ผู้ใหญ่ 18+ · บรรยากาศ LGBTQ+ / Gay Adult Party · Mobile-First

เอกสารนี้เป็น **แหล่งอ้างอิงหลักของวิธีเล่นและกติกาเฉพาะเกม** ใช้ประกอบการออกแบบ UX, เขียนโปรแกรม, สร้างชุดคำถาม และทดสอบเกม ก่อนเริ่ม Implement ให้ตรวจสอบโค้ดจริงและทวนข้อเสนอที่ยังไม่อนุมัติอีกครั้ง

**แยกหน้าที่เอกสาร:** [`GAME-DEVELOPMENT.md`](GAME-DEVELOPMENT.md) กำหนดมาตรฐานทางเทคนิค, [`FIREBASE.md`](FIREBASE.md) กำหนด Auth/ข้อมูล, ส่วนไฟล์นี้อธิบาย **ผู้เล่นต้องทำอะไร กติกาเป็นอย่างไร และเมื่อไรจบเกม** โดยไม่ทำซ้ำคู่มือ Infrastructure

## 1. 🌈 หลักการร่วมของทั้ง 11 เกม

### 1.1 แนวทางประสบการณ์

- ผู้เล่นต้องมีอายุ **18 ปีขึ้นไป** ตามนโยบายการเข้าถึง; หน้า “ฉันอายุ 18+” เป็นเพียง **age gate** ไม่เท่ากับการตรวจสอบอายุที่กฎหมายบางเขตกำหนด
- ใช้ภาษาขำ ๆ หยอกแรง ทะลึ่ง และบรรยากาศเซ็กซี่ได้ตามระดับเกม แต่ **ไม่บังคับเปิดเผยประสบการณ์ทางเพศหรือข้อมูลส่วนตัว**
- ผู้เล่นสามารถ **Skip / Mute / Exit / Report** ได้ตลอด ไม่มีการหักคะแนนหรือประจานจากการข้ามคำถามที่อ่อนไหว
- เกมแนวปาร์ตี้ใช้ **ชื่อเล่น** ได้ และควรมีโหมด **เล่นหน้าจอเดียว (Pass & Play)** ก่อนขยายเป็นห้องออนไลน์
- ภาพนายแบบ/คาแรกเตอร์ที่ใช้ต้องเป็นผู้ใหญ่ มีสิทธิ์ใช้งานและความยินยอมที่ตรวจสอบได้; ห้ามใช้รูปผู้เยาว์ ภาพหลุด ภาพคนจริงโดยไม่มีสิทธิ์ หรือสร้างคำถามเพื่อเปิดเผยตัวตนที่อ่อนไหว
- `SPICY`, `HOT`, `XXX`, `AFTER_DARK` เป็น **content classification** ไม่ใช่สิทธิ์ผ่านเข้าเกม; กำหนด `accessPolicy`, `contentWarnings`, `mediaRightsStatus` แยกจาก `contentRating`
- หากเพิ่มสื่อเปลือยหรือเนื้อหาที่โจ่งแจ้งขึ้น ต้องตรวจข้อกฎหมายไทย/ประเทศเป้าหมายและนโยบาย Hosting/CDN/Payment ก่อนปล่อย Production; **ไม่มีเกมใดบังคับต้องใช้สื่อเปลือย**
- คะแนน/Badges/Rankings ที่มีผลต่อบัญชีต้องยืนยันผ่าน Trusted Server; คะแนนจาก Browser ถือเป็นข้อมูลที่ยังไม่ผ่านการตรวจสอบ

### 1.2 คำศัพท์และค่าเริ่มต้น (Proposed Defaults)

| คำ | ความหมาย / ค่าเริ่มต้น |
| --- | --- |
| **Solo** | เล่นคนเดียวบนอุปกรณ์เดียว |
| **Party / Local** | 2–12 คน เล่นบนจอเดียวหรือผลัดกันส่งเครื่อง; บางเกมรองรับมากกว่าได้ภายหลัง |
| **Online Room** | ห้องหลายอุปกรณ์แบบ Real-time — **อนาคต ไม่อยู่ใน MVP เว้นแต่กำหนดเพิ่ม** |
| **Round** | หนึ่งคำถาม/หนึ่งสถานการณ์/หนึ่งโหวต |
| **Session** | ชุดรอบเล่นต่อเนื่อง ตั้งแต่เริ่มจนสรุปผล |
| **Unranked** | เล่นสนุก ไม่ส่งขึ้น Leaderboard หรือ XP ที่แข่งขันกัน |
| **Ranked** | มีระบบตรวจผลฝั่ง Server เพียงพอ จึงส่งขึ้น Leaderboard ได้ |
| **Skip** | ข้ามรอบนั้นโดยไม่ต้องให้เหตุผล; ห้ามใช้การข้ามมาลงโทษด้านสังคม |
| **Prompt Pack** | ชุดคำถามที่ผ่านการตรวจเนื้อหา มี `packId`, `version`, `rating`, `locale` |

**ค่าเริ่มต้นสำหรับเกมปาร์ตี้:** รอบละ 30–60 วินาทีเมื่อมีการจับเวลา, 10 รอบต่อ Session, ช่วงตัวเลือก 5/10/15 รอบ; ผู้ดูแลห้องสามารถเปลี่ยนก่อนเริ่มได้ ผู้เล่นเลือกโหมดความเข้มของเนื้อหาภายในสิทธิ์ที่ได้รับ

### 1.3 ขั้นตอนมาตรฐานของทุกเกม

`Game Lobby → Game Details + Content Warning → Age/Access Check → เลือกโหมดและจำนวนรอบ → How to Play → เริ่ม → เล่น/ข้าม/ออก → สรุปผล → เล่นอีกครั้งหรือกลับ Lobby`

หากผู้เล่นออกกลางเกมให้ยกเลิก Timer/Listener, ไม่ลงอันดับจากรอบที่ยังไม่จบ และไม่แอบบันทึกคำตอบที่เป็นข้อมูลอ่อนไหวโดยไม่จำเป็น

### 1.4 กติกาการทำคะแนนร่วม

- **เกมคำตอบมีถูกผิด** ใช้คะแนนตามกติกาแต่ละเกมและตรวจชุดข้อ/คำตอบฝั่ง Server; ห้ามฝังเฉลยที่ใช้กับ Ranked ลง Client โดยไม่จำเป็น
- **เกมโหวต ความชอบ หรือสารภาพ** ไม่มี “คำตอบถูก” และไม่ควรเอาความเปิดเผยเรื่องส่วนตัวมาแข่งขัน; ตั้งต้นเป็น **Unranked**
- **Tie-break** สำหรับเกมที่มี Ranked: คะแนนสูงกว่า → จำนวนตอบถูกมากกว่า → เวลาเสร็จที่ Server ยืนยันเร็วกว่า (หากกติกานั้นใช้เวลา) → ถ้ายังเท่ากันให้แสดงอันดับร่วม
- คำตอบ/บันทึกเกมปาร์ตี้เป็นข้อมูลชั่วคราวโดยปริยาย; ไม่เผยแพร่บนโปรไฟล์หรือ Leaderboard โดยไม่ได้รับความยินยอมเฉพาะเจาะจง

## 3. 🍆 GAME 01 — SIZE MATTERS?

**สโลแกน:** “ดูให้ดี อย่าคิดลึก!” · **Genre:** Visual Guess / Comedy · **Rating:** `SPICY`

**เป้าหมาย:** ทายขนาด ความยาว น้ำหนัก หรือสัดส่วนของ **วัตถุทั่วไป/ภาพเงาที่ได้รับสิทธิ์** จากภาพและคำใบ้สองแง่สองง่าม โดยเกมเฉลยข้อมูลจริงอย่างขำ ๆ

**จำนวนผู้เล่น:** Solo 1 คน; Party 2–12 คนแบบผลัดกันตอบหรือยกป้ายคำตอบ

**วิธีเล่นทีละขั้น**
1. เลือก **Quick Play (5 ข้อ)** หรือ **Full Play (10 ข้อ)** และเลือกระบบหน่วยที่จะแสดง (ค่ามาตรฐานเป็นเซนติเมตร/กรัมตามโจทย์)
2. เกมแสดงภาพเงาหรือภาพครอป + คำใบ้ พร้อม 4 ตัวเลือก เช่น `5 / 10 / 15 / 20 ซม.`
3. ผู้เล่นเลือกคำตอบภายใน **15 วินาที**; ปุ่ม Skip ผ่านได้โดยไม่เสียคะแนน
4. เมื่อหมดเวลา/ตอบแล้ว เฉลยรูปเต็ม ชื่อวัตถุ และข้อเท็จจริงสั้น ๆ ก่อนเข้าสู่ข้อถัดไป
5. ครบทุกข้อ แสดงคะแนน จำนวนตอบถูก และชวนแชร์ผลแบบไม่ระบุข้อมูลส่วนตัว

**คะแนน:** ตอบถูก `+100`; ตอบผิด/หมดเวลา/Skip `0`; โบนัสเวลา **ไม่มีใน MVP** เพื่อให้เกมยุติธรรมและทดสอบง่าย; สูงสุด 500/1,000 คะแนน

**ตัวอย่าง:** คำใบ้ “ยาว ๆ เอาไว้กินตอนเช้า” → ภาพเงาขนมปังบาแกตต์; เฉลยต้องมีแหล่งข้อมูลหรือขนาดที่ทีมสร้างคอนเทนต์กำหนดแน่นอน ไม่สุ่มเฉลยตามใจ

**เงื่อนไขจบ:** ครบจำนวนข้อ; คำถามห้ามซ้ำใน Session เดียว ถ้าคลังไม่พอให้แจ้งก่อนเริ่ม

**ขอบเขต MVP:** Question bank, รูปภาพพร้อม alt text, Multiple Choice, Timer, Score Summary; **ไม่มี** การให้ผู้เล่นอัปโหลดรูปอวัยวะหรือสัดส่วนร่างกายคนจริง

**ทดสอบสำคัญ:** หน่วยวัดสอดคล้องกับคำตอบ, เวลา 0 วินาที, Double Tap, รูปโหลดไม่สำเร็จ, จำนวนข้อไม่ครบ, คำถามไม่ซ้ำ

## 4. 😈 GAME 02 — NEVER HAVE I EVER

**สโลแกน:** “ไม่เคยเหรอ... แน่ใจนะ?” · **Genre:** Party Confession · **Rating:** `AFTER_DARK`

**เป้าหมาย:** ชวนเพื่อนหัวเราะกับประสบการณ์เดต ความสัมพันธ์ และวีรกรรม 18+ โดยทุกคนมีสิทธิ์ไม่ตอบ

**จำนวนผู้เล่น:** 2–12 คน (Solo ใช้โหมดอ่านการ์ดได้ แต่ไม่มีโหวตกลุ่ม)

**วิธีเล่นทีละขั้น**
1. ตั้งชื่อเล่นผู้เล่น เลือก `Mild / Spicy / After Dark` และจำนวน 10/20/30 การ์ด
2. เกมสุ่มข้อความ “ฉันไม่เคย...” เช่น “ฉันไม่เคยส่งข้อความหาแฟนเก่าตอนตีสอง”
3. ผู้เล่นแต่ละคนเลือก **เคย / ไม่เคย / ข้าม** แบบสมัครใจ; กรณีเล่นเครื่องเดียวให้ใช้วิธีเปิดเผยพร้อมกัน หรือเลือกปิดการบันทึกรายบุคคล
4. สรุป **จำนวนคนที่เลือกตอบว่าเคยเท่านั้น** หากทุกคนยินยอม; ไม่เปิดชื่อว่าใครตอบอะไรโดยอัตโนมัติ
5. กด Next จนครบการ์ดและแสดงไฮไลต์คำถามฮา ๆ แบบ **ไม่เก็บประวัติคำตอบส่วนตัว**

**คะแนน:** **ไม่มีคะแนนหรือผู้ชนะ** ไม่ใช้การดื่ม การถอดเสื้อ หรือการเปิดเผยเรื่องส่วนตัวเป็นบทลงโทษ

**ข้าม/ไม่พร้อม:** Skip ได้เสมอ; หากผู้เล่นไม่ต้องการเปิดคำตอบให้รองรับ “เล่นแบบไม่บันทึกคำตอบ”

**กติกาคอนเทนต์:** หลีกเลี่ยงคำถามเกี่ยวกับการ outing คนอื่น, รายละเอียดที่ระบุตัวบุคคล, การละเมิดความยินยอม หรือการกดดันเล่าประสบการณ์ทางเพศ

**จบเกม:** ครบจำนวนการ์ด หรือ Host จบห้องก่อน; ล้างคำตอบชั่วคราวหลังจบ Session

**ทดสอบสำคัญ:** ผู้เล่น Skip ทุกคน, ปิดเสียง, เริ่มใหม่, เปลี่ยนแพ็กคำถาม, ไม่มีการส่งคำตอบส่วนบุคคลไป Analytics

## 5. 🍑 GAME 03 — TOP, BOTTOM OR VERS?

**สโลแกน:** “ทายคาแรกเตอร์ ไม่ใช่ตัดสินคนจริง” · **Genre:** Fictional Character Quiz · **Rating:** `SPICY`

**เป้าหมาย:** อ่านสถานการณ์/บทสนทนาจาก **ตัวละครสมมติที่เขียนไว้ชัดเจน** แล้วเดาว่าผู้เขียนออกแบบคาแรกเตอร์ให้ตอบ `Top / Bottom / Vers / Plot Twist` แบบมุกตลก

**จำนวนผู้เล่น:** Solo หรือ Party 2–12 คน

**วิธีเล่นทีละขั้น**
1. เลือก 5 หรือ 10 ฉาก
2. อ่านการ์ดตัวละครสมมติพร้อมคำบอกบริบทว่า “เกมแต่งเรื่องเพื่อความบันเทิง”
3. เลือก 1 จาก 4 ตัวเลือก ไม่มีการสแกนหน้า เสียง เสื้อผ้า หรือประวัติผู้เล่น
4. แสดงเฉลย **ตามบทเขียนของตัวละคร** พร้อมมุกหรือบทต่อ ไม่อ้างว่าเป็นข้อเท็จจริงทางจิตวิทยา
5. รวมผลเป็น “คุณเดาพล็อตเก่งแค่ไหน” ไม่ออกใบรับรองรสนิยมทางเพศ

**คะแนน:** `+100` สำหรับคำตอบตรงบทเฉลย; `0` สำหรับอื่น ๆ; **เป็นคะแนนสนุกเฉพาะ Session และ Unranked** เพราะคำเฉลยเป็นกลไกเล่าเรื่อง ไม่ใช่คุณสมบัติที่วัดได้จริง

**ตัวอย่างฉาก:** “อเล็กซ์ชอบสลับบทเป็นฝ่ายนำหรือฝ่ายตามในนิยายที่ตัวเองแต่ง” → เฉลย `Vers` **เฉพาะในเรื่องสมมตินี้**

**สิ่งห้าม:** ห้ามทายหรือยืนยันบทบาททางเพศของบุคคลจริงจากภาพ/บุคลิก/สเตอริโอไทป์ ห้ามให้คนอื่นกรอกชื่อคนจริงเพื่อให้เกม “วิเคราะห์”

**จบเกม:** ครบทุกฉาก แสดงการ์ดผลขำ ๆ ไม่เก็บผลเป็นข้อมูลตัวตนผู้เล่น

## 6. 🔥 GAME 04 — SMASH OR PASS

**สโลแกน:** “ถูกใจหรือเลื่อนไป?” · **Genre:** Swipe / Taste Match · **Rating:** `HOT`

**เป้าหมาย:** เลือกความชอบด้านภาพลักษณ์และสไตล์จากภาพ **คาแรกเตอร์สมมติหรือผู้ใหญ่ที่มีสิทธิ์ใช้ภาพ** อย่างสนุกโดยไม่ให้คะแนนหน้าตาเชิงเหยียดหยาม

**จำนวนผู้เล่น:** Solo 1 คน; Party Mode เปรียบเทียบความชอบโดยสมัครใจ (เฟสถัดไป)

**วิธีเล่นทีละขั้น**

## 13. 🪩 GAME 11 — GAY BATTLE ROYALE

**สโลแกน:** “ตอบให้ไว อยู่ให้รอด ตัวแม่คนสุดท้าย!” · **Genre:** Elimination Trivia · **Rating:** `SPICY`

**เป้าหมาย:** แข่งตอบ Quiz เรื่องวัฒนธรรม LGBTQ+ เพลง ปาร์ตี้ หนัง และความรู้ทั่วไปแบบขำ ๆ เพื่อเหลือผู้ชนะคนสุดท้าย

**จำนวนผู้เล่น:** MVP **Party 2–12 คนบนอุปกรณ์เดียว**; Online Live Room เป็นเฟสถัดไป; Solo ฝึกตอบได้โดยไม่มี elimination

**วิธีเล่นทีละขั้น**
1. Host ตั้งชื่อเล่น เลือกหมวดความรู้และจำนวนรอบ **5/10**; ทุกคนรับรู้ว่าคำถามเป็น Quiz ไม่ใช่ข้อเท็จจริงเกี่ยวกับเพศวิถีของผู้เล่น
2. ระบบสุ่มโจทย์แบบ 4 ตัวเลือก มีเวลา **15 วินาที** ต่อข้อ
3. ใน MVP แบบเครื่องเดียว ใช้ **ผลัดกันตอบชุดคำถามเทียบเท่ากัน** เพื่อไม่ให้เห็นคำตอบคนอื่น; ยังไม่ใช่การตอบพร้อมกันแบบ Live
4. เมื่อจบรอบ คำนวณคะแนนสะสม; คนคะแนนต่ำสุดถูกคัดออก **เฉพาะถ้ามีอย่างน้อย 3 คนเหลืออยู่**
5. หากคะแนนต่ำสุด **เสมอกัน** ให้ทุกคนที่เสมออยู่ต่อและเพิ่มรอบ Tie-break; ห้ามสุ่มตัดออกโดยไร้กติกา
6. เล่นจนเหลือ 1 คน หรือถึงจำนวนรอบสูงสุด; ถ้ายังเสมอเมื่อหมดชุด Tie-break ให้ประกาศ **ผู้ชนะร่วม**

**คะแนน:** ตอบถูก `+100`; ตอบผิด/Skip/หมดเวลา `0`; ไม่มี Speed Bonus ใน MVP; ตำแหน่งอันดับใช้คะแนนสะสมจากโจทย์ที่มีความยากเทียบเท่ากัน

**ความยุติธรรมของ MVP:** การผลัดกันใช้เครื่องเดียวอาจทำให้เห็นโจทย์/คำเฉลยได้ จึงให้สถานะ **Unranked** จนกว่าจะมีระบบป้องกันการเห็นคำตอบและตรวจผลที่เหมาะสม; หากผู้เล่นน้อยกว่า 3 คน ให้ใช้การแข่งขันแบบสะสมคะแนน ไม่มีการคัดออกกลางเกม

**คำถามต้อง:** มีแหล่งอ้างอิงเมื่ออาศัยข้อเท็จจริงที่อาจเปลี่ยนได้; รองรับไทย/อังกฤษ; คัดกรองสเตอริโอไทป์และความเข้าใจผิดเรื่องเพศ/สุขภาพ

**จบเกม:** ได้ผู้ชนะ 1 คน, ผู้ชนะร่วม, หรือ Host End; แสดงผลอย่างสุภาพ ไม่ประจานผู้ตกรอบ

**ทดสอบสำคัญ:** 2 คน, 3 คน, 12 คน, เสมอหลายคน, คำถามไม่พอ, ไม่กดตอบ, ผู้เล่นออก, เข้ารอบสุดท้าย

## 14. ⚙️ มาตรฐานข้อมูลคำถามและเกม (Content Contract)

ตัวอย่าง **schema เชิงแนวคิด** (ห้ามใช้เป็นหลักฐานว่ามี Collection/ไฟล์จริง):

```ts
export type ContentRating = "SPICY" | "HOT" | "XXX" | "AFTER_DARK";
export type GameStatus = "draft" | "review" | "published" | "archived";

export interface GameRulesDefinition {
  id: string;               // stable game ID
  slug: string;             // URL route
  rulesVersion: string;     // e.g. "1.0.0"
  title: { th: string; en: string };
  contentRating: ContentRating;
  status: GameStatus;
  modes: Array<"solo" | "party-local" | "online-room">;
  minPlayers: number;
  maxPlayers: number;
  ranked: boolean;          // true เฉพาะมี server verification
  accessPolicyId: string;   // แยกจาก rating
}

export interface PromptCard {
  id: string;
  packId: string;
  version: number;
  locale: "th" | "en";
  text: string;
  contentRating: ContentRating;
  contentWarnings: string[];
  status: "draft" | "approved" | "retired";
  // เฉลย/รูบริกสำหรับการแข่งขันควรอยู่บน Trusted Server เท่านั้น
}
```

**Workflow สำหรับคำถาม/ภาพ:** Draft → Editorial Review → Legal/Media Rights Review (ตามประเภทสื่อ) → Rating/Access Review → Publish → Report/Unpublish → Retire. ใช้ `rulesVersion` สำหรับกติกาและ `packId/version` สำหรับเนื้อหาแยกกัน

**การเก็บข้อมูล:** ค่าความชอบ, การสารภาพ, การโหวตเพื่อน หรือฉากเดตที่เลือก **ไม่ใช่ข้อมูลที่ต้องซิงก์กับบัญชีโดยค่าเริ่มต้น**; เก็บเท่าที่จำเป็น ชั่วคราว และไม่เผยแพร่ต่อบุคคลอื่น; หากต้องมี analytics ใช้ตัวชี้วัดรวมแบบลดการระบุตัวตน

**ภาพ/สื่อที่จำกัดสิทธิ์:** อย่าพึ่งพาการเบลอภาพหรือซ่อนปุ่มเพื่อบังคับ access; ต้องจำกัดการส่งไฟล์จาก Origin/CDN/Storage ด้วย นำสื่อออกได้เมื่อสิทธิ์หมดหรือได้รับคำร้องเรียน

## 15. 🧪 Acceptance Criteria ก่อนเริ่มและก่อนปล่อยแต่ละเกม

- [ ] ผู้เล่นเข้าใจเป้าหมายและวิธีเล่นในหน้า How to Play ไม่เกิน 3–5 ขั้นตอน
- [ ] ระบุจำนวนผู้เล่น, โหมด, จำนวนรอบ, เงื่อนไขจบ, การข้ามและการเสมอชัดเจน
- [ ] ระดับเนื้อหา, age/access rules, คำเตือน และสิทธิ์ของสื่อผ่านการตรวจ
- [ ] คลังคำถามมีคำตอบ/เฉลยและเวอร์ชันที่คงที่สำหรับเกมแข่งขัน
- [ ] Solo/Party ใช้งานได้บนมือถือจริง และไม่มีการสร้าง Timer/Listener ซ้ำ
- [ ] เกมที่ไม่มีหลักฐานตรวจคะแนนจาก Server ต้องเป็น **Unranked**
- [ ] การกดย้อนกลับ ออกจากเกม หมดเวลา การส่งซ้ำ และเครือข่ายล้มเหลวไม่ทำให้ข้อมูลผิดเพี้ยน
- [ ] Skip/Exit ใช้ได้จริง ไม่มีการลงโทษจากการไม่เปิดเผยประสบการณ์ส่วนตัว
- [ ] ไม่มีการเผยแพร่ข้อมูลอ่อนไหว/ผลโหวตรายคนโดยไม่ได้รับความยินยอม
- [ ] ทดสอบภาษาไทย/อังกฤษและข้อจำกัดของคำตอบ/ภาพในแต่ละภาษาก่อนเผยแพร่
- [ ] ตรวจสิทธิ์ Firebase/Content Access ฝั่ง Server และตรวจนโยบายสื่อ 18+ ก่อน Production
- [ ] บันทึกผลการทดสอบจริง แยกจากสิ่งที่ยังอยู่ระหว่างออกแบบ

## 16. 🚀 ลำดับทำงานที่แนะนำหลังเอกสารนี้

1. **รับรองกติกา MVP**: ตัดสินใจเรื่องจำนวนรอบ/เวลา/คะแนน/โหมดให้ถือเป็น `rulesVersion = 1.0.0`
2. **ทำ UI Flow + Design System** สำหรับ Lobby, How to Play, Game Shell, Results, Rating Warning
3. **สร้าง Content Packs ที่ผ่านการตรวจ** เริ่ม 30–50 การ์ดต่อเกมคำถาม (ไม่ฝังเฉลย Ranked ใน Client)
4. **พัฒนา MVP ตามความง่าย:** `dirty-mind` → `red-flag-detector` → `size-matters` → เกม Party แบบ Local → เกม Story → Battle Royale
5. **เชื่อม Auth/Firestore หลังทดสอบความจำเป็นจริง** โดยไม่สร้าง Global Leaderboard ให้เกมโหวต/สารภาพ
6. **QA และตรวจการเผยแพร่ 18+** ทั้งเรื่องความยินยอม สิทธิ์สื่อ คำเตือน การจำกัดอายุ และข้อกำหนดผู้ให้บริการ

> **หมายเหตุ:** กติกา ตัวเลขคะแนนและรอบในไฟล์นี้เป็น **ข้อเสนอเพื่อพัฒนา MVP** ไม่ใช่ข้อกำหนดทางธุรกิจที่ยืนยันแล้ว หากเปลี่ยนกติกาที่กระทบผลการแข่งขัน ให้เพิ่ม `rulesVersion` และทดสอบย้อนหลังอย่างเหมาะสม
